범위: 2026-10-17 공개 `https://w8385.dev/Pokemon-Champions-Assistant/`의 홈·실능 스피드라인·샘플 라이브러리·샘플 빌더·도감. 데스크톱 1280×577, 도감 모바일 390×844의 DOM/좌표와 소스 `af21370`을 대조했다. **관찰**은 실제 동작/코드, **제안**은 아직 구현하지 않은 설계다. 브라우저 5개 직접 route와 각 목적 행동은 `actual.json`; 이미지는 `builder-modal.png`, `dex-mobile.png`. ## 공통 규칙·경계와 검증

1. **8개 상단 목적지 전부 직접 링크**: 숨김·더보기·드롭다운 회귀 금지. 데스크톱에서는 메뉴와 언어/백업 유틸리티를 한 행의 양 끝에, 모바일은 직접 링크를 줄바꿈하고 390px에서 가로 overflow 없이 모두 보여준다. 현 DOM은 시각 `h1.visually-hidden` + route `h2`이며 유틸만 윗줄, nav는 다음줄(`App.tsx:6989-7044`; `styles.css:8436-8442`). 모든 route에는 의미상 주 heading 하나(사이트명은 로고/label로 처리), 하위 section heading 계층을 유지. 부모 실측 `../parent-single-baseline.json`의 싱글 카드 top 1041.86/900 및 4개 inline-controls 링크 UA blue `rgb(0,0,238)` on dark `rgb(18,25,35)`는 전체 재발 방지 근거: 공통 다크 링크 토큰으로 visited/hover/focus 포함 색/대비, 메뉴와 본문 액션의 일관성을 확인한다. 스크린샷 CJK 네모를 디자인 결함으로 판정하지 않는다.
2. **액션 위계**: primary 한 개는 현 작업의 다음 단계, secondary는 편집/상세, destructive는 명확한 확인. 링크(목적지)와 버튼(현재 상태 변경) 구분. 홈 첫 의도→1회 이동, 스피드/도감은 검색/기준 선택부터, 라이브러리는 찾기→출처 상세→가져오기, 빌더는 편집→별도 저장/적용; 설명문을 늘리는 대신 초기 결과를 빨리 보여준다. 빈/로딩/오류/부분 근거를 실제 상태로 구분: 검색 0건 필터 초기화, 알 수 없는 상세 ID 원본/목록 복귀, import 불가 이유, 숫자 입력 오류 시 오래된 수치 숨기기, 저장 실패/복구 노출. 현재 라이브러리 0건·불명 ID 메시지는 `App.tsx:8808,8827`, 속도 0건/입력 경고는 `SpeedLinePanel.tsx:91,133-146`.
3. **저장 소유권**: 라이브러리는 출처 있는 읽기 전용 원본, 빌더는 수정 가능한 초안/개인 SavedSample, 내 파티는 실제 등록 슬롯, speed/dex는 조회·가정. 상세→빌더 import→저장→파티 적용의 각 전환에서 이름/폼·도구·특성·노력·4기술·출처/확인 정도를 보존하고, 파티 교체는 명시 확인. 부분 빌드의 import 차단, 완전한 파티 사전 검증, source-specific proof, field-level 출처, 원본 폼의 종족값과 unknown 성격/실수치 구분은 불변(`App.tsx:6396-6410,6950-6984,8773-8805`). `savedSamples`/파티/route 저장 체계와 과거 URL·백업 migration 검증 없이 스키마나 링크를 바꾸지 않는다(`App.tsx:1690-1755,5126`).
4. **공용 컴포넌트와 입력 계약**: `PokemonCardOverview.tsx`의 heading/stat/readonly 카드와 `RegisteredMoveSlot`, `PokemonSearchField.tsx`, 노력치 모달의 실제 callbacks/툴팁/readonly/focus를 공유한다. 검증된 데이터와 미확인을 섞지 않고, 검색은 표시·화살표 highlight·Enter commit 동일 ranked list, IME composition/229 중 Enter 오선택 금지, 닫힌 제안 Enter 금지. `dexDescriptions.json` 전체 eager import 금지; 필요 필드만 lazy/기존 경계 유지. 로컬 저장 복원·백업은 기존 migration 테스트와 함께 확인한다.

## 작은 배포 단위와 합격 게이트

- **P0 이동 계약/안전** (`App.tsx:7612-7625,4196,5141,8770-8805`): 도감→빌더 tab 고정 재현 결함부터 수정; 파티 슬롯/샘플 원본 교체는 확인 흐름. 직접 8 URL, 라이브러리 상세 뒤로, 이전 tab을 거친 이동, reload/백업 복구와 import blocked/complete를 자동+공개 브라우저에서 재검증. 새 저장 스키마 migration 없이 근거 필드가 유실되지 않아야 한다.
- **P1 한 화면의 결정을 당기기** (`App.tsx:7173-7257,7359-7414,9683-9769`, `SpeedLinePanel.tsx:101-146`): 홈 시작 카드, 도감 단일 검색-결과-상세, 빌더 저장/적용 대상과 speed 기준→결과의 순서 조정. 각 route 초기 화면에서 검색/선택 또는 다음 작업 도달; 모바일 390px에서 결과와 주요 액션의 실제 좌표·overflow를 검사한다.
- **P2 공통 프레임/디자인** (`App.tsx:6989-7044`, `styles.css:80-116,8436-8442`, `PokemonCardOverview.tsx`): 데스크톱 메뉴+유틸 한 행, 모바일 8 직접링크 줄바꿈, 다크 링크 토큰, heading/카드/empty 상태 정렬. 1280×900·390×844에서 8링크 active/Enter/새탭/뒤로/scrollWidth 및 색상·대비 실측; CJK glyph는 별도 실제 사용자 환경에서만 확인.

범위 밖: 새 메뉴, OAuth, 추천 알고리즘, 추가 긴 설명문, 출처 미확인 자료의 자동 수집/완전 빌드 취급, 기존 8개 링크 축소, 앱 구현. 모달을 연 뒤 다른 route로 이동하면 DOM상 모달이 남는 관찰도 있었지만 이번 설계에서는 ‘화면 전환 시 편집 모달 닫기/초안 유지’ 회귀 확인 항목으로만 둔다; 별도 사용자 데이터 변경은 하지 않았다.
