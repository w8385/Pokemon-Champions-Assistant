기존 8개 직접 메뉴는 유지한다. 새 메뉴·계정·계산 엔진은 만들지 않는다.

- 내 파티: 등록·수정이 먼저다. 전체 카드 아래에서 타점·약점을 확인한다.
- 싱글: 저장된 내/상대 엔트리 하나씩 고르면 같은 두 카드로 속도와 양방향 4기술 피해를 본다.

- 라이브러리: 출처 있는 원본을 찾고 확인한다. 읽기와 가져오기를 구분한다.
- 빌더: 한 마리 초안을 수정한다. 개인 샘플 저장과 파티 슬롯 적용은 서로 다른 행동이다.
- 스피드라인: 기준 대비 전체 폼의 속도와 추월 투자를 탐색한다.
- 도감: 정보를 찾고 확인한다. 편집으로 넘어갈 때 대상과 목적지를 명시한다.
- 홈: 위 작업을 바로 고르는 길찾기 화면이다. 소개 문구가 시작 행동을 밀어내지 않는다.

## 실제 문제

1. 싱글의 엔트리 선택과 계산기 내부 종 선택이 이중으로 존재한다. 상단 슬롯과 하단 포켓몬이 달라질 수 있다.
2. 싱글에서 공수 교체를 누르면 하단 카드만 뒤집힌다. 상단 내/상대 선택은 그대로여서 화면의 포켓몬 정체성이 충돌한다.
3. 카드 위에 선택 패널, 별도 대면 제목, 긴 조건 설명, 스피드 카드, 선택 기술 결과를 누적했다. 공개 모바일 실측 첫 카드 시작점은 문서 y=1974px였다.
4. 파티 카드와 비교 카드가 제목·능력치·기술·모달 일부만 공유한다. 특성·성격·도구 입력은 팝오버와 native select로 갈라져 있다.
5. 라이브러리 방문 뒤 도감에서 빌더로 열면 라이브러리로 돌아가는 경로가 재현됐다.
6. 싱글 보조 링크 4개는 어두운 배경 위 기본 파란색이다. 공통 프레임·테마 규칙이 일부 신규 화면에 적용되지 않았다.

이 목록은 수정 완료 목록이 아니다. 재현 근거와 한계는 아래 감사 문서에 있다.

## 싱글 목표 구조

한 작업면 안에서 다음 순서로 읽는다.

1. 내 엔트리 / 상대 엔트리를 선택한다.
2. 내 카드 / 상대 카드는 위치와 종이 고정된다. 싱글 안에서 다른 종을 다시 검색하지 않는다.
3. 같은 대상의 속도를 공통 0기준 막대, 수치, 차이로 비교한다.
4. 각 카드의 2×2 기술칸 아래에서 해당 방향 피해를 바로 확인한다.
5. 선택 기술의 난수·장막·상태 등은 상세로 연다. 공수는 기술의 출발 방향이지 카드의 소유권이 아니다.

종족값·성격/노력·랭크·스카프의 요약은 양쪽 같은 순서로 유지한다. 긴 가정 설명은 해당 필드의 가정 표시와 펼칠 수 있는 상세로 옮긴다. 잘못된 조합이나 미확인 수치를 숨겨 정상 계산처럼 보이게 만들지 않는다.

데스크톱 목표는 첫 화면에서 두 대상과 주요 결과를 함께 보는 것이다. 모바일은 카드를 쌓되 두 대상·속도 요약과 방향을 잃지 않고 기술 결과로 바로 이어지게 한다. 작은 화면에 억지로 두 전체 카드를 가로 배치하지 않는다.

## 실제 공용화 기준

- `PokemonCardHeading`, `PokemonStatGrid`, `RegisteredMoveSlot`, `EffortTuningModal`의 실제 렌더·콜백을 보존한다.
- 특성·성격·도구는 기존 파티 입력의 검색·팝오버·키보드 동작까지 추출해 재사용한다. 이름만 같은 wrapper를 새로 만들지 않는다.
- 비교 화면은 공용 뷰 하나를 사용하고, 엔트리 모드와 독립 모드는 종을 고르는 방식과 저장 어댑터만 다르게 연결한다.
- 싱글 선택 슬롯은 부모가, 비교 중 가정은 대면 모델이 소유한다. 다른 슬롯·폼·화면으로 이동하면 가정과 열린 모달을 초기화한다.
- 저장 파티, 상대 기록, 대면 가정, 독립 계산 저장을 서로 덮어쓰지 않는다.

## 작은 구현 순서와 합격 조건

### 0. 이번에 반영하는 위치 이동

파티 전체 카드 그리드 다음에 기존 타점·약점 패널 한 개를 둔다. 엔진·저장 데이터는 바꾸지 않는다. 빈 파티/6마리, 데스크톱/모바일의 실제 순서와 상세 버튼을 검증한다.

### 1. 싱글의 대상 정체성 고정

싱글의 내부 자유 종 검색과 카드 맞교환을 분리한다. 상단 선택=카드=속도 대상이 내 슬롯 A→B→A, 상대 교체, 기술 방향 전환 후에도 일치해야 한다. 독립 계산기의 검색·맞교환은 유지한다. 원본 불변, 가정 초기화, 모달 대상 초기화를 자동·실제 화면으로 확인한다.

### 2. 싱글을 한 작업면으로 통합

분리된 선택/속도/결과 패널을 같은 두 카드의 흐름으로 재배치한다. 4기술×양측의 실제 입력과 피해, 속도 요약을 전면에 둔다. 빈 결과 상자와 중복 제목을 제거한다. 1280×900 및 390×844에서 카드/첫 유효 결과까지 거리와 스크롤을 이전 실측보다 줄인다. 기술 하나만 있어도 계산하고 툴팁·노력치 모달·검색 Enter는 유지한다.

### 3. 기존 작업 간 이동과 입력 통일

도감→빌더의 목적지를 확정하고, 라이브러리 원본→빌더 초안→저장→파티 적용을 구분한다. 파티 변경은 대상을 먼저 보여주고 확인한다. 실제 입력 컴포넌트를 공용화한 뒤 같은 필드·조건에 대해 모든 호출부를 재검사한다.

### 4. 공통 프레임과 보조 도구 정리

데스크톱 메뉴·유틸리티를 같은 행으로, 모바일 직접 링크는 줄바꿈으로 둔다. 다크 링크·버튼·제목·빈 상태를 통일한다. 홈은 시작 행동을 앞에, 도감은 검색 소유권을 하나로, 스피드라인은 기준 선택과 결과를 먼저 둔다. 상태 복원·직접 URL·뒤로/새로고침·키보드·모바일을 메뉴별로 재검증한다.
