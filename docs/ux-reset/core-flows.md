## 첫 구현 1조각과 이후 순서 [제안, 이 문서에서 구현하지 않음]

**첫 조각:** 싱글 `#/single?tab=party`만 부모 선택을 유일한 종 identity로 고정하고, 카드 위치를 내/상대에 고정한다. 두 내부 검색을 엔트리 모드에서 제거/비활성화하고 싱글 공수 버튼은 기술 방향 선택으로 대체한다. 양 카드의 실제 기존 카드/4기술과 공통 스피드·피해 미리보기를 한 화면 구조로 끌어올리되 계산 함수는 유지. 독립 `/damage`의 검색·맞교환·저장은 회귀 금지.

**수락 기준:** 1280×900·390×844 실렌더에서 상단 선택=두 카드 종=스피드 이름이 슬롯 1→2→1, 상대 교체, 기술 방향 전환 후 항상 일치; 종 identity를 바꾸는 싱글 카드 내부 검색 0개(독립 계산은 2개); 양측 4개 기술 slot 2×2와 각 입력 하단 미리보기, 유효 기술 1개만으로 결과; 양쪽 속도 동일 0기준 척도+부호/동속, 카드보다 앞에 별도 큰 결과·스피드-person 둘을 두지 않음; 스크롤 길이·첫 결과 도달 거리 실측 개선; 포커스/툴팁/모달/가정 초기화와 원본 불변·reload 확인; 독립 calculator 검색/교체/localStorage 회귀 통과. 현행 비교 기준 1280×900 카드 시작 y=1072, 390×844 첫 카드 y=1974·둘째 y=2903. 이 수치는 개선 목표가 아닌 현재 baseline.

**다음 순서:** (1) 위 mounted QA/회귀 후 독립 간단 대미지를 같은 비교 카드 뷰로 소비하게 하고 독립 persistence 분리 유지; (2) 내 파티 진입/빈 슬롯/카드 아래 분석/저장→싱글 전환; (3) 나머지 5개 정보·샘플/속도 메뉴의 첫 행동·상세 단계·빈 상태/모바일 접근성 순차 감사 및 개선. 메뉴 삭제, 선출추정 부활, 계정/OAuth·유료 API, 신규 계산 엔진, 이번 문서 작업에서 UI 수정은 범위 밖.

## 측정 한계

실제 공개 브라우저의 기저 데이터는 이미 6+6 슬롯이 채워져 싱글 **빈 엔트리**는 변경 없이 재현 불가했다. 기록의 `mobile-empty-slot` 태그는 6번 슬롯이 비었을 것이라는 초기 가정으로 수집되었으나 실제 ‘대도각참’으로 채워진 것이 확인돼 빈 상태 근거로 **사용하지 않는다**. `mobile-opponent-slot-6`도 마스카나로 채워졌다. 독립 `/damage`의 검색 2개/선택 전 메시지만 빈 상태 근거로 사용한다. 터치 기기 물리 입력·시각 글리프는 평가하지 않았고 DOM rect/스크롤 및 실제 클릭 결과만 근거로 사용한다.
