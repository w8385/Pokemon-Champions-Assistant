# 메뉴 선택 후 닫힘 수정

## 원인

메뉴 링크는 모바일 메뉴 상태만 false로 바꿨음. 하위 메뉴의 native details.open 상태는 라우트 변경 뒤에도 남아 있었음.

## 변경

- 홈과 모든 하위 메뉴 링크에서 기존 모바일 닫기와 함께 primary-navigation의 펼친 details를 닫음.
- 같은 메뉴를 다시 선택해도 닫힘. 라우트 상태 변경에 의존하지 않음.
- 링크 기본 동작은 막지 않음. 계산·파티·저장 데이터는 변경하지 않음.

## 실제 검증

- 공개 기존 화면에서 샘플 메뉴를 펼친 뒤 라이브러리를 선택해도 open=true로 남는 문제 재현함.
- 실제 App 링크 이벤트 회귀 테스트2개: 수정 전 FAIL, 수정 후 PASS.
- 전체146/146 테스트·타입·빌드·diff 검사 PASS.
- 로컬 브라우저: 홈/싱글/더블/샘플 빌더/라이브러리/스피드라인/도감 링크7개 전부 목적지 이동 후 펼친 그룹0개와 모바일 상태false 확인함.
- 같은 도감 메뉴 재선택, 실제 Enter 키 선택 후 그룹0개 확인함.
- 모바일390px에서 선택 뒤 그룹0개·토글false·nav display:none 확인함.
- 독립 리뷰 및 공개 배포 확인은 후속 릴리스 근거에 기록함.

근거: browser workspace의 header-menu-close-qa.json.
