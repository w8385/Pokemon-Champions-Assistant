# Pinned item-description inputs

`item-description-primary.json` is a narrow extraction of 119 missing canonical item keys (38 ordinary, 81 form-locked stones; all 119 have game-text rows). It was joined from Project Pokémon `champout` commit `50e7233b78c3b81df29563f9695386c28e77fc95`: `masterdata/item.json` (`id`, `ms_lbl`, `ms_lbl_info`) and `rom-txt/{kor,usa,jpn}/{itemname,iteminfo_syn}.json` (`mSDataSet[].LabelName` → `OriginalText`). Before extraction, all seven raw files were checked byte-for-byte against the SHA-256 digests in `item-description-manifest.json`; those upstream files total approximately 0.8 MB, so only the 119 source-backed joins are retained here. Fixture and historical rows are independently hashed in the manifest for offline generation. The original raw files remain retrievable at that pinned commit; this source snapshot is **not** proof of present-game legality or regulation parity.

`item-description-historical.json` freezes the 43 pre-existing PokeAPI-backed entries unchanged (including their historical `itemId`, names and text). The new game-text `sourceItemId` occupies a different namespace and is never assigned to `itemId`. The former 120-key candidate set included `とつげきチョッキ` without a source row. Following the user's non-introduction report, it is excluded from the offered item set and the producer inputs, not represented as an unknown offered item. The 43 historical entries remain byte-for-byte unchanged, and 43 + 119 = 162 descriptions. The one explicit spelling alias is canonical `후딘나이트` ↔ source KO `후디나이트`, corroborated by source ID 679, EN `Alakazite` and JA `フーディナイト`. Names are NFKC-normalized **only for matching** (e.g., fullwidth Ｘ/Ｙ/Ｚ); original strings and line breaks are retained. `unlock` flags do not authorize held items.

Run `python3 scripts/build_item_descriptions.py` to regenerate the item section of `src/canonical-data/dex/dexDescriptions.json` offline; `--check` compares bytes without writing. The general `build_dex_descriptions.py` invokes the same pinned item producer instead of fetching historical PokeAPI item descriptions. Its move/ability sync remains network-dependent and is not the offline item verification path. CI runs the offline check before build. Read-only Dex browsing now includes the complete ordinary+required-stone identities; battle held-item authorization remains separate.
